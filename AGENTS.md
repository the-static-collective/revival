# Revival operating law

These rules apply to the whole repository.

## Preserve ancestry

- Never silently rewrite a held witness to make a descendant easier to produce.
- Corrections, normalizations, translations, and interpretations are descendants with explicit provenance.
- A projection may be lossy only when its delta says what was lost.
- A receipt describes an actual declared transform; it is not evidence that an interpretation is true.

## Keep the kernel small

- Kernel primitives are identity and derivation mechanics, not textual, theological, or scholarly authority.
- Format-, corpus-, model-, and provider-specific behavior belongs outside the frozen kernel.
- Do not add a dependency to kernel code when the same contract can remain in the Python standard library.

## Evolve with scissors

- Existing kernel generations are immutable ancestry.
- A breaking kernel change creates a named descendant generation with explicit parent identity and rationale.
- Never change an old kernel contract and continue calling it the same frozen generation.

## Keep choice separate from authority

- Reader preference selects among declared descendants; it does not rewrite a witness or linguistic layer.
- A selectable rendering must retain its own declared provenance and authority boundary.
- Unknown or undeclared preference values fail closed.
- Preference profiles are presentation inputs, not evidence that a rendering is correct.

## Proof before claim

- Executable behavior needs focused tests.
- Determinism claims require replay evidence.
- Lossless/lossy claims require delta assertions.
- Report only checks that actually ran.

## Authority

Revival may preserve, transform, compare, project, and expose provenance. It does not decide canon, translation quality, theology, historical truth, or human acceptance.
